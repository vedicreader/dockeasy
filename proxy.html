proxy

Write Caddyfiles, and the Compose services for Caddy, CrowdSec and Cloudflare Tunnel.

Caddyfile builder

Caddy is a web server that is often run as a reverse proxy. It receives the requests for your domain from the internet, fetches and renews an HTTPS certificate for the domain by itself, and passes each request to your app. Its config file is called a Caddyfile. A Caddyfile can start with a global block in braces, for settings such as the ACME account email, and then has one block per site.

Caddyfile builds a file with one site. Give it the domain and the name and port of the app to forward to; in a Compose stack, the app’s name is its service name. Each method adds a setting and returns a new Caddyfile:

  • email sets the address for the ACME account that requests certificates.
  • acme_dns gets certificates with a DNS-01 challenge through a DNS provider’s API, for when port 80 cannot be reached from outside. The token is read from the environment variable named by token_env.
  • cloudflared serves the site over plain http://, for use behind a Cloudflare Tunnel, which handles HTTPS itself. It also tells Caddy to trust the private addresses the tunnel arrives from and to read the visitor’s address from the Cf-Connecting-Ip header, so logs and client_ip show the visitor instead of the tunnel.
  • crowdsec checks each visitor’s IP address with a CrowdSec agent at api_url and blocks known attackers. The agent’s URL and key go in a global crowdsec block, the site block gets the crowdsec handler, and the global order crowdsec first runs it before every other handler. The plugin registers no place in Caddy’s directive order.
  • rate_limit allows each IP address requests requests per window.
  • max_body caps the size of a request body.
  • encode turns on response compression, which Caddy leaves off by default. Name the encodings to choose them and their order, as in encode('zstd', 'gzip').
  • log turns on access logs. They go to stderr unless you pass output: a file path such as '/var/log/caddy/access.log', or a Caddy log writer such as 'stdout', 'discard' or 'net localhost:9999'. A file output rotates with roll_size (such as '50MiB'), roll_keep (files kept) and roll_keep_for (such as '2160h'); format sets the encoder, such as 'json'.
  • spa serves a single-page app’s static files from static_dir instead of forwarding to the app, and answers any path that is not a file with index.html.
  • upstreams forwards to several copies of the app, one per port in ports, such as one per worker process. The keywords become reverse_proxy options: lb_policy picks how requests are shared, lb_try_duration and lb_try_interval retry a failed request on another copy, and health_uri, health_interval, health_timeout and fail_duration take a copy out of rotation while it fails its health check. With handle=True the proxy sits inside a handle block, which you need when raw blocks use handle with a matcher: Caddy runs only the first handle that matches, so the proxy becomes the fallback.
  • raw adds a block of Caddyfile text as it is, for directives the builder has no method for. Indent its lines after the first with tabs as they should appear.
  • comment adds a # line to the site block, and notes adds comments at the ends of lines. notes takes a dict from the start of a line, such as 'encode', to its comment.

The file ends with a newline, and a blank line separates the global block from the site.

The DNS provider behind acme_dns, and the crowdsec and rate_limit settings, come from Caddy plugins that the official caddy:2 image does not include. The image you run must have them built in. caddy_svc below picks such an image for Cloudflare DNS and for CrowdSec.

Caddyfile presets

Most sites need only a few of those settings. caddy builds a Caddyfile from keyword arguments, one per option, and returns it; nothing is written until you call .save(). dns is ignored when cloudflared=True, because behind a tunnel Caddy fetches no certificates at all. The token variable defaults to the provider’s name in capitals followed by _API_TOKEN, such as CLOUDFLARE_API_TOKEN.

caddy_api is caddy with settings suited to an API: a limit of 200 requests a minute from each IP address, a 50 MB cap on request bodies, and compression. The examples below print the file each combination writes.

def caddy(
    domain, # domain to serve, such as example.com or app.example.com
    app:str='app', # name of the app to forward to; in Compose, its service name
    port:int=5001, # port the app listens on

    access_log:bool=False, # log every request to stderr; Caddy writes no access log by default

Services

These functions return the settings for one Compose service, as a dict to pass to Compose.svc with **. Every service joins a network called web and restarts unless you stop it, so declare .network('web') in the stack.

caddy_svc writes the Caddyfile from caddy to conf and returns the Caddy service. The service mounts that Caddyfile, keeps certificates and state in the caddy_data and caddy_config volumes, starts after the app service, and publishes ports 80 and 443 unless cloudflared=True. It also picks an image that has the plugins your options need:

options image
none, or only cloudflared=True caddy:2
crowdsec=True serfriz/caddy-crowdsec:latest
dns='cloudflare' serfriz/caddy-cloudflare:latest
dns='cloudflare' and crowdsec=True ghcr.io/buildplan/csdp-caddy:latest

For any other DNS provider, pass an image with that provider’s plugin as image, as the duckdns test below does. The service passes the DNS token and CROWDSEC_API_KEY through from the host’s environment. An absolute conf is mounted from that path. A relative one is mounted as ./ plus its file name, so in that case save the Compose file in the same folder as the Caddyfile. mount sets the mounted path yourself, such as ./Caddyfile for an absolute conf beside the Compose file. Pass your own Caddyfile as caddyfile to write it instead of the one built from the options, or save=False to write nothing.

cloudflared_svc returns the Cloudflare Tunnel service. The cloudflared container connects out to Cloudflare and carries your site’s traffic back over that connection, so the server needs no open inbound port. token_env is the value given to the container’s TUNNEL_TOKEN; the default, ${CF_TUNNEL_TOKEN}, makes Compose read the token from the host’s CF_TUNNEL_TOKEN variable. Where the tunnel sends traffic is normally set in the Cloudflare dashboard, and url passes it on the command line instead, for example url='http://caddy'.

CrowdSec keeps a shared list of IP addresses known for attacks, and Caddy’s CrowdSec plugin asks a local CrowdSec agent about each visitor. crowdsec returns the agent service. collections are the CrowdSec rule sets it installs; the default covers Linux, Caddy and known HTTP exploits. The agent registers a bouncer, CrowdSec’s name for a client that enforces its decisions, called caddy, with the key from the host’s CROWDSEC_BOUNCER_KEY variable. caddy_svc(crowdsec=True) gives Caddy its key from CROWDSEC_API_KEY, so set both variables to the same value. The agent keeps its data and config in the crowdsec-db and crowdsec-config volumes, which the stack must declare.

  • Stack A: Caddy fetches certificates itself, and ports 80 and 443 are open.
  • Stack B: a Cloudflare Tunnel carries the traffic, and no port is open.
  • Stack C: stack B with CrowdSec checking visitors.
  • Stack D: Caddy gets its certificate with a DNS-01 challenge through Cloudflare, with the ports open and no tunnel.

Integration test: FastHTML, Caddy and cloudflared

This test starts a real stack and checks that the app can be reached over the internet. It is skipped in the docs build and by nbdev_test. To run it you need:

  • a Cloudflare Tunnel, created in the Cloudflare Zero Trust dashboard under Tunnels, with its token in the CF_TUNNEL_TOKEN environment variable;
  • a public hostname on that tunnel that sends traffic to http://caddy;
  • DOMAIN, set at the top of the cell, changed to that hostname.

The cell writes a FastHTML app, builds it with fasthtml_app, and starts the app, Caddy and cloudflared. It then requests https://DOMAIN every 10 seconds for up to two minutes and prints the container logs. Whether or not the check passes, it takes the stack down and removes the image.

DOMAIN = 'fastops.angalama.com'
# Compose reads CF_TUNNEL_TOKEN from the host environment.

app_dir = Path(tempfile.mkdtemp(dir='.'))
(app_dir / 'app.py').write_text('''\
from fasthtml.common import *
app, rt = fast_app()

@rt('/')
def get(): return Titled('dockeasy-proxy-test', P('Caddy + cloudflared ✓'))

serve()
''')
(app_dir / 'pyproject.toml').write_text('''\
[project]
name = "proxy-test"
version = "0.1.0"
dependencies = ["python-fasthtml", "starlette<0.46"]
''')
fasthtml_app().save(app_dir / 'Dockerfile')

tag = 'dockeasy-proxy-test:latest'

inf_dir = Path(tempfile.mkdtemp(dir='.'))

    .svc('app', build=str(app_dir), image=tag, networks=['web'], restart='unless-stopped')
    .svc('caddy', **caddy_svc(DOMAIN, cloudflared=True, conf=cf_path))
    .svc('cloudflared', **cloudflared_svc(url='http://caddy'))
    .network('web').volume('caddy_data').volume('caddy_config'))

print(dc)

print(Path(cf_path).read_text())

try:
    dc.up(path=dc_path)
    print('Waiting for cloudflared tunnel to connect...')
    html = None
    for i in range(12):
        time.sleep(10)
        try: html = urlread(f'https://{DOMAIN}'); break
        except Exception as e: print(f'  [{(i+1)*10}s] not ready: {e}')
    print('=== container logs ===')
    print(dc.logs(path=dc_path))
    assert html and 'dockeasy-proxy-test' in html, f'Unexpected response: {html[:200] if html else "no response"}'
    print(f'✓ App reachable at https://{DOMAIN}')
finally:
    dc.down(path=dc_path, v=True, remove_orphans=True)
    rmi(tag, force=True)
    print('Cleaned up.')
